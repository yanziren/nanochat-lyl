# 13条独立提示词 + 一条【组合黄金顺序总提示词】
你可以单独复制任意一条给大模型，针对任意技术概念（Transformer、梯度、DDP、reduce_scatter、损失函数等）执行对应讲解手法。

---
## 1. 最小可解释玩具案例（Toy Example）提示词
```
请使用【最小可解释玩具案例】方式讲解【{在这里填入概念名称}】。
要求：
1. 砍掉所有冗余变量、复杂分支，只保留1~2条核心逻辑；
2. 使用整数、简单数值，搭建最小规模场景，完整手动跑通一遍全流程；
3. 一步一步演算，让听众可以跟着手动走一遍；
4. 不要引入额外无关知识点，数值尽量取整数，减少计算负担；
5. 最后一句话总结这个最小案例能说明什么核心机制。
讲解对象：有基础编程认知，但是第一次接触这个概念的学习者。
```

## 2. 动机溯源法提示词
```
请使用【动机溯源法】讲解【{在这里填入概念名称}】。
要求：
1. 先不讲定义，先讲这个技术诞生之前存在什么痛点、旧方案是什么、旧方案致命缺陷是什么；
2. 讲清楚工程师是为了解决哪一个具体问题才设计出这个方案；
3. 痛点讲完之后，再给出它的定义、它的作用；
4. 最后说明：理解这个痛点之后，可以推导出它哪些天然特性。
不要一上来直接甩公式、代码、术语定义。
```

## 3. 结构化类比与隐喻提示词
```
请使用【结构化类比与隐喻】讲解【{在这里填入概念名称}】。
要求：
1. 挑选听众熟悉的日常事物/系统，做一对一严格映射，输出一张对照表：一边是技术概念，一边是现实对应事物；
2. 类比不能随便打比方，每一个组件都要有对应关系；
3. 讲完类比之后，必须明确标注类比边界：哪些地方相似、哪些地方不一样，防止把类比当成事实；
4. 语言通俗，不要堆砌专业术语。
```

## 4. 可视化与几何直观提示词
```
请使用【可视化与几何直观】方式讲解【{在这里填入概念名称}】。
要求：
1. 把这个概念的时序流程、数值关系、空间变换，转化为可以直接看懂的图方案；
2. 如果适合流程图，输出Mermaid流程图代码；如果适合几何变换，用文字描述坐标/变换过程；
3. 关键步骤高亮标注；
4. 说明动态演示该怎么动、每一步变化是什么；
5. 解释图形里面每一个元素代表什么含义。
```

## 5. 分层拆解法（黑盒→白盒自上而下）提示词
```
请使用【分层拆解法】讲解【{在这里填入概念名称}】。
要求：
1. 第一层：当成黑盒，只讲输入、输出、整体核心功能；
2. 第二层：拆开黑盒，介绍里面2~3个核心子模块；
3. 第三层：在子模块听懂的前提下，再深入内部细节；
4. 严格自上而下，先整体后局部，不一开始就扎进细节；
5. 每一层结束后做简短小结。
```

## 6. 物理/现实意义锚定法提示词
```
请使用【物理/现实意义锚定法】讲解【{在这里填入概念名称}】。
要求：
1. 如果有公式，把公式里每一个符号、每一项单独拿出来；
2. 给每一项绑定现实含义、业务含义，不要只讲数学符号；
3. 解释每一项存在的目的：它是用来解决什么问题、起到什么效果；
4. 解释清楚：去掉这一项之后，整个公式会出现什么问题。
```

## 7. 反例与边界界定法提示词
```
请使用【反例与边界界定法】讲解【{在这里填入概念名称}】。
要求：
1. 先简单说清楚它正常成立的条件；
2. 然后列出：什么场景下这个方法不成立、失效；
3. 违反哪一条假设就会出问题；给出具体反例；
4. 说明误用之后会出现什么现象；
5. 最后总结它的适用边界清单。
```

## 8. 相近概念对比辨析提示词
```
请使用【相近概念对比辨析】讲解【{概念A} 和 {概念B}】。
要求：
1. 从四个固定维度对比：核心目的、数学形式/实现方式、适用场景、优缺点；
2. 做成清晰对比表格；
3. 重点标注学习者最容易混淆的地方；
4. 一句话总结什么时候该选A，什么时候选B。
```

## 9. 推导路径还原法提示词
```
请使用【推导路径还原法】讲解【{在这里填入概念/公式名称}】。
要求：
1. 不直接抛出最终结论、公式；
2. 还原思考路径：从原始问题出发，列出基础假设，一步步试错、修正；
3. 沿着思考路径自然推导出最终公式/算法；
4. 每一步推导说明为什么要做这个假设，假设不成立会怎么样；
5. 最后给出最终结论。
```

## 10. 极端值压力测试法提示词
```
请使用【极端值压力测试法】讲解【{在这里填入概念/公式}】。
要求：
1. 找出里面所有可调参数；
2. 分别把参数推到极端值：0、无穷大、最大值、最小值；
3. 观察每一个极端情况下公式/机制退化成什么样子；
4. 解释每个极端状态对应的行为、风险；
5. 通过极端行为，反向说明这个参数原本的作用。
```

## 11. 跨领域等价映射法提示词
```
请使用【跨领域等价映射法】讲解【{在这里填入概念名称}】。
要求：
1. 找到这个概念在另一个领域里的等价结构；
2. 建立映射关系，说明两者底层思想完全一致；
3. 用听众已经掌握的另一领域知识来解释；
4. 明确提醒：这个映射只适合有对应领域基础的学习者，新手不要用；
5. 区分底层共性和表层差异。
```

# 总提示词（黄金顺序组合版，优先用这个！）
```
请按照固定黄金顺序讲解【{在这里填入概念名称}】：动机溯源 → 结构化类比 → 最小可解释玩具案例 → 可视化演示 → 边界与反例 → 相近概念对比。
每一段严格对应这套讲解方法，顺序不能乱：
1. 动机溯源：先讲旧方案痛点、为什么要发明它，再引出这个概念；
2. 结构化类比：一对一映射日常事物，输出对照表，并且标注类比边界；
3. 最小可解释玩具案例：用简单整数，最小场景完整跑通一遍流程；
4. 可视化：输出Mermaid流程图或者文字几何示意图；
5. 边界与反例：讲清楚什么时候失效、反例；
6. 相近概念对比：和最容易混淆的概念做对比（核心目的、形式、场景、优缺点）；
全程面向有编程基础的学习者，不要跳关键逻辑，每一步讲完可以加简短小结。
```
